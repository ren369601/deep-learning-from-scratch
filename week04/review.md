## 知识题

1. 输入 `X` 为 `(20, 2)`，隐藏层为 `(20, 16)`，logits 为 `(20, 2)`，整数标签为 `(20,)`。第一层权重/偏置分别是 `(16, 2)`、`(16,)`；第二层是 `(2, 16)`、`(2,)`。总参数数目为 `16*2 + 16 + 2*16 + 2 = 82`，与代码输出一致。

2. `model.train()` 和 `model.eval()` 切换模块行为，例如 Dropout 和 BatchNorm；它们不会自动训练或锁定参数。只有计算梯度并调用优化器的 `step()` 才会更新参数。评估还使用 `torch.no_grad()` 避免建立求导图，但这也不等于禁止调用 `step()`。

3. `nn.CrossEntropyLoss` 接收原始 logits 和整数类别标签，内部进行数值稳定的归一化与对数损失计算。预先手动 Softmax 会让它把概率再当作 logits 处理，目标函数就变了。

4. PyTorch 默认把新梯度累加进 `.grad`。本次对相同数据和未更新的模型连续反向两次，第一层 bias 的梯度约变成原来的两倍；`model.zero_grad()` 后再反向，梯度回到单次计算的数值。

5. `optimizer.step()` 改变了参数。更新前计算的 logits 和 loss 仍对应旧参数；只有重新前向，训练与验证指标才对应当前同一组参数。

6. 这可能是过拟合信号，但先检查数据切分、标签、评估模式、指标计算和随机波动，再观察多个 epoch 的趋势。这里验证集只有 20 个样本，单次波动不足以下结论；需要更可靠的数据和独立测试集判断泛化。

## 本周易混点（下次自查）

- `eval()` 控制层行为，`no_grad()` 控制求导图，`zero_grad()` 清空累积梯度，`step()` 更新参数；四者不能互相替代。
- `CrossEntropyLoss` 用 logits；Softmax 仅在需要展示类别概率时额外计算。
- 本次梯度累积实验没有更新参数，所以连续两次计算的是同一个梯度，才能直接观察到约两倍的关系。
