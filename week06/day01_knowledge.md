# Week 6 / Day 1：一步一步看懂卷积

先用一句话描述今天的计算：

**把一张小表盖在大表的一部分上，对应位置相乘，把乘积加起来；移动小表，重复这件事。**

“大表”是输入图像，“小表”是卷积核，“盖住的部分”是窗口，每次得到的一个数字放进输出表。

这句话里还不需要公式。先用纸笔把下面的数字算一遍，再对应到代码。

## 怎么读这份讲解

第一遍读第 1-5 节，理解一个输出数字来自哪里；第二遍读第 6-8 节，理解步长、填充和尺寸；最后读第 9-12 节，把运算对应到 PyTorch。

今天先处理一张单通道图像。多通道和完整网络会在后续逐步学习。建议分成两次阅读，每次 30-45 分钟，再做代码练习。

## 1. 先认清输入表、行列与位置

### 1.1 图像怎么变成数字

灰度图中，每个像素用一个数表示亮暗。今天用一张虚构的 3×3 小图方便计算：

~~~text
image =
[[1, 2, 3],
 [4, 5, 6],
 [7, 8, 9]]
~~~

它有 3 行、3 列。shape=(3,3)，第一个 3 是行数，第二个 3 是列数。

真实图像的像素可以有不同的数值范围；这里的 1 到 9 只是练习数字。

### 1.2 Python 从 0 开始数位置

~~~text
             第0列  第1列  第2列
第0行           1      2      3
第1行           4      5      6
第2行           7      8      9
~~~

所以 image[0,0] 是 1，image[1,2] 是 6。

注意：(1,2) 表示“第 1 行、第 2 列”，是位置；6 才是这个位置存放的数值。计算窗口时要把位置与数值分清。

**停一下：image[2,1] 是多少？** 沿第 2 行找到第 1 列，应得到 8。

## 2. 卷积核是什么

卷积核 kernel 也是一张数字表，只是通常比图像小。今天使用：

~~~text
kernel =
[[1,  0],
 [0, -1]]
~~~

它的 shape=(2,2)。这四个数是四个位置的权重。

可以把它读成一条规则：

~~~text
窗口左上角乘 1
窗口右上角乘 0
窗口左下角乘 0
窗口右下角乘 -1
把四项加起来
~~~

所以这个特定核计算的是“窗口左上角的值减去右下角的值”。

核中的数也可以是其他值。例如四项都是 0.25，就会计算 2×2 窗口的平均值。核决定如何组合局部数字。

今天核的值已经给定。训练 CNN 时，这些权重通常通过梯度更新来学习。

## 3. 只算第一个窗口，暂时不要移动

### 3.1 什么叫窗口

核有 2 行、2 列，因此先从输入左上角取一块同样大小的区域：

~~~text
输入图像：                  取出的窗口：
[[1, 2, 3],                 [[1,2],
 [4, 5, 6],                  [4,5]]
 [7, 8, 9]]
~~~

窗口是输入的一部分，核是权重。它们大小相同，但含义不同。

### 3.2 四个位置各自相乘

~~~text
窗口             核                对应位置乘积
[[1,2],          [[1, 0],           [[1*1, 2*0],
 [4,5]]           [0,-1]]            [4*0, 5*(-1)]]

乘积表 =
[[1,  0],
 [0, -5]]
~~~

### 3.3 把乘积表加成一个数字

~~~text
1 + 0 + 0 + (-5) = -4
~~~

这一次计算得到一个数字 -4，放到输出的左上角：

~~~text
output =
[[-4, ?],
 [ ?, ?]]
~~~

**一个窗口经过乘加，产生一个输出位置。** 输出不是把四个乘积原样保留下来。

### 3.4 为什么代码是乘法再 sum

~~~python
window = image[0:2, 0:2]
value = (window * kernel).sum()
~~~

逐行读：

- image[0:2,0:2] 取第 0、1 行和第 0、1 列，因为切片不包含右端的 2。
- window*kernel 对应位置相乘，得到上面的乘积表。
- .sum() 把表里的四个数加起来。

这里使用逐元素乘法 *。矩阵乘法 @ 有另一套行列组合规则，不是刚才的四个位置对应相乘。

## 4. 移动窗口，算完剩下三个位置

今天先约定每次移动一格，图像边缘也先不补数字。

### 4.1 向右移动一格

这次取输入的第 0、1 行，第 1、2 列：

~~~text
window = [[2,3],
          [5,6]]

2*1 + 3*0 + 5*0 + 6*(-1) = -4
~~~

结果放到输出的第 0 行、第 1 列：

~~~text
output =
[[-4,-4],
 [ ?, ?]]
~~~

继续向右就放不下完整的 2×2 窗口了，所以转到下一行的起点。

### 4.2 回到左边，向下移动一格

~~~text
window = [[4,5],
          [7,8]]

4*1 + 5*0 + 7*0 + 8*(-1) = -4

output =
[[-4,-4],
 [-4, ?]]
~~~

### 4.3 再向右一格

~~~text
window = [[5,6],
          [8,9]]

5*1 + 6*0 + 8*0 + 9*(-1) = -4

output =
[[-4,-4],
 [-4,-4]]
~~~

这张输出表叫特征图 feature map。四个位置都复用同一个核，核的权重不会随着移动而自动变换。

### 4.4 为什么这里的结果全都一样

因为这个输入恰好让每个窗口的“左上减右下”都等于 -4。

只把输入中间的 5 改成 10，保持核不变：

~~~text
新输入：
[[1, 2, 3],
 [4,10, 6],
 [7, 8, 9]]

新输出：
[[-9,-4],
 [-4, 1]]
~~~

左上窗口变成 1-10=-9，右下窗口变成 10-9=1。另两个窗口中，改动的像素乘到的核权重是 0，因此结果仍为 -4。

这说明输出由输入窗口和核共同决定，不是核一旦给定，所有输出就固定相同。

## 5. 输出的负数表示什么

-4 是当前加权规则的计算结果。它可以为负，也可以为正，并不自动是类别或概率。

这个核对局部数值差异产生响应。换一个核可能得到平均值或其他局部模式的响应。实际网络会把这些结果继续送到后续层。

如果另加 ReLU，-4 会变成 0，但那是下一步激活运算。今天手写函数只完成窗口乘加，返回原始结果。

如果再加偏置 b=2，每个输出在乘加结果基础上加 2，例如 -4 变成 -2。今天作业先不加偏置。

## 6. 步长 stride：窗口起点每次隔几格

### 6.1 stride=1

刚才 3×3 输入、2×2 核的窗口起点为：

~~~text
(0,0)  (0,1)
(1,0)  (1,1)
~~~

共 2 行、2 列输出。

这里说的“起点”是窗口左上角在输入中的位置。

### 6.2 stride=2

每次向右或向下移动两格。仍用刚才的 3×3 输入和 2×2 核：

~~~text
第一个起点：(0,0)，能放下。
下一个横向起点：(0,2)，需要第 2、3 列，但输入没有第 3 列。
下一个纵向起点：(2,0)，需要第 2、3 行，但输入没有第 3 行。
~~~

因此只得到 1×1 输出：

~~~text
[[-4]]
~~~

stride=2 是改变窗口的移动距离，不是核内部隔着像素取值；后者属于以后学习的空洞卷积概念。

### 6.3 看一个更长的边

输入某一边有 5 个位置，核占 3 个位置：

~~~text
输入位置：0 1 2 3 4

stride=1：
第1次取 [0 1 2]
第2次取   [1 2 3]
第3次取     [2 3 4]

stride=2：
第1次取 [0 1 2]
第2次取     [2 3 4]
~~~

所以这一边分别有 3 个或 2 个输出位置。先数窗口，再看公式，会更容易理解。

## 7. 填充 padding：先把输入表变大

### 7.1 padding=1 的“1”是什么意思

意思是在上、下、左、右**每一侧补一层 0**。

~~~text
原输入：
[[1,2,3],
 [4,5,6],
 [7,8,9]]

补边后：
[[0,0,0,0,0],
 [0,1,2,3,0],
 [0,4,5,6,0],
 [0,7,8,9,0],
 [0,0,0,0,0]]
~~~

原来 3 行，现在 5 行：上面加 1 行，下面加 1 行，所以是 3+2，而不是 3+1。宽度同理。

填充只增加边缘位置，原图中间的数字保持不变。

### 7.2 补边后怎样计算

仍然用同一个 2×2 核。填充后左上窗口变成：

~~~text
window = [[0,0],
          [0,1]]

0*1 + 0*0 + 0*0 + 1*(-1) = -1
~~~

如果窗口起点来到填充后输入的 (1,1)，取到的就是原图左上窗口 [[1,2],[4,5]]，输出仍为 -4。

所以 padding 改变了哪些位置能够放窗口，也引入了边界上的额外计算；它不是把整个输出简单补零。

### 7.3 为什么要补边

不填充时，窗口必须完整留在原图里。补边后，核可以覆盖原图边缘及其外侧的零位置，让输出尺寸可控。

例如 3×3 输入、3×3 核、stride=1：
不补边只放得下 1 次；每边补 1 层后变成 5×5，就能得到 3×3 输出。

今天使用零填充。其他边界处理方法以后可以再了解。

## 8. 输出尺寸公式：其实是在数起点

### 8.1 先只看高度

设处理后的高度是 5，核高是 3，步长是 1。窗口的合法起点为 0、1、2。

为什么最后起点是 2？因为 2 开始占用第 2、3、4 行，刚好放得下；从 3 开始就会超出输入。

因此：

~~~text
最后允许的起点 = 处理后高度 - 核高 = 5-3 = 2
~~~

从 0 到 2，每次前进 1，一共 3 个起点。加 1 是把最初起点 0 也算进去。

### 8.2 步长不能整除时怎么办

处理后高度为 6、核高为 3、stride=2：

~~~text
最后允许起点 = 6-3 = 3
实际按步长走：0、2
下一个是 4，超过 3，不能使用。
~~~

因此输出高度是 2。最后可能有一行没有被任何窗口覆盖，这是步长约定产生的正常结果。

公式用向下取整表示“只计算完整放得下的次数”。

### 8.3 再加上 padding

| 符号 | 表示什么 |
|---|---|
| H | 原输入高度，行数 |
| W | 原输入宽度，列数 |
| Kh、Kw | 核的高和宽 |
| P | 每一侧补几层零 |
| S | 窗口每次移动几格 |
| H_out、W_out | 输出高和宽 |

~~~text
补边后的高度 = H+2*P
最后允许的行起点 = H+2*P-Kh
起点数量 = floor((H+2*P-Kh)/S)+1

所以：
H_out = floor((H+2*P-Kh)/S)+1
W_out = floor((W+2*P-Kw)/S)+1
~~~

floor 表示向下取整，例如 floor(2.5)=2。在检查分子非负且 S>0 后，可以用 Python 的 // 计算。

### 8.4 把一道题完全展开

输入高 6、宽 7；核高 3、宽 2；stride=2，padding=1。

先计算补边后尺寸：

~~~text
高度：6+1+1 = 8
宽度：7+1+1 = 9
~~~

再数窗口起点：

~~~text
纵向：核占3行，最后允许起点8-3=5。
按步长2走：0、2、4，共3个。

横向：核占2列，最后允许起点9-2=7。
按步长2走：0、2、4、6，共4个。
~~~

所以输出 shape=(3,4)。与公式核对：

~~~text
H_out = (6+2*1-3)//2+1 = 5//2+1 = 3
W_out = (7+2*1-2)//2+1 = 7//2+1 = 4
~~~

今天假设核内部相邻、步长为正整数、四边对称零填充。如果填充后输入仍小于核，应报错。空洞卷积与更复杂参数组合后面另讲。

## 9. “卷积”与“互相关”的名字放到这里理解

前面所有计算都保持核的方向不变。这种操作严格称为二维互相关，英文 cross-correlation。

数学卷积会先将核旋转 180 度：

~~~text
原来的核：        旋转180度：
[[1, 0],         [[-1,0],
 [0,-1]]          [ 0,1]]
~~~

对同一个左上窗口 [[1,2],[4,5]]：

~~~text
不翻转：1-5 = -4
翻转后：-1+5 = 4
~~~

PyTorch 的 Conv2d 采用不翻转的互相关，实际使用中仍叫卷积层。今天的函数 manual_corr2d 也不翻核，这样能够与 PyTorch 的结果直接对应。

转置只交换行列，旋转 180 度是同时反转行顺序和列顺序。代码 torch.flip(kernel,dims=(0,1)) 表示后者。

今天先把“滑动、逐项相乘、求和”学会；名字差异放在这个计算约定上理解即可。

## 10. 图像为什么又出现四个维度

前面一张灰度图是 (H,W)。PyTorch 常用的批次表示还需要回答另外两个问题：

第一，这批有几张图？用 N 表示。
第二，每张图有几个通道？用 C 表示。

灰度图可以先理解为一个亮度通道。RGB 彩色图有红、绿、蓝三个通道，相当于同一张图对应三张二维数值表。多通道的计算明天再展开。

~~~text
(N,C,H,W)

(1,1,3,3)：
1张图，每张1个通道，每个通道3行3列。

(8,3,28,28)：
8张图，每张3个通道，每个通道28行28列。
~~~

它们不是“4 张图”或“8×3 张图”；每一维有自己的含义。

### 增加长度为1的维度

~~~python
image.shape                       # (3,3)
image.unsqueeze(0).shape          # (1,3,3)
image.unsqueeze(0).unsqueeze(0).shape  # (1,1,3,3)
~~~

像素值还是原来的 9 个，只是多了表示通道和批次的轴。取 batch[0,0] 可以回到第一张图的第一个通道，即原来的二维表。

今天手写函数接收二维输入，因此可以先专注 (H,W)。调用库函数做验证时，再增加这两个轴。

## 11. 从手算走到代码，逐句对应

### 11.1 输出位置与输入起点有时不同

输出位置记为 (i,j)。它是第几个窗口，不一定等于窗口在输入上的位置。

~~~text
row_start = i*stride
col_start = j*stride
~~~

例如 stride=2 时，输出 (1,1) 对应填充后输入的窗口起点 (2,2)。输出向右走一格，输入窗口向右走两格。

### 11.2 切片末尾怎样写

假设窗口从输入第 1 行、第 0 列开始，核高宽都为 2：

~~~python
window = image[1:1+2, 0:0+2]
~~~

也就是取第 1、2 行和第 0、1 列：

~~~text
[[4,5],
 [7,8]]
~~~

这说明“起点加核尺寸”是右端边界。Python 不包含右端，才能恰好取两行、两列。

### 11.3 为什么循环输出尺寸

输出高为 H_out、宽为 W_out，就有 H_out*W_out 个需要填写的位置。每个位置找一次窗口、算一次乘加。

如果直接循环原输入所有位置，靠近边缘的窗口可能不完整。先算好输出尺寸，就知道哪些窗口合法。

### 11.4 填充为什么先做好

先创建尺寸为 (H+2P,W+2P) 的全零表，再把原图放进中间。后续所有窗口都从这张表取，计算过程中无需分别处理上边、下边、左边和右边。

~~~python
padded[P:P+H, P:P+W] = image
~~~

它表示在 padded 的中间一块写入原图数值。P=1 时原图从第 1 行、第 1 列开始放；P=0 时从第 0 行、第 0 列放。

## 12. 常见卡点对照

| 疑问 | 可以这样核对 |
|---|---|
| 核与窗口是不是同一个东西？ | 核是权重表，窗口是从输入取出的局部数据 |
| 一个窗口为什么只得到一个数？ | 四项乘积最后被 sum 加成一个数 |
| 输出为什么可能为负？ | 权重可为负，加权和自然可为负 |
| 移动窗口时核会重新抽样吗？ | 一次前向中复用同一组核权重 |
| stride=2 是否隔着取核内部像素？ | 它移动窗口起点；核内部今天仍连续取值 |
| padding=1 为什么尺寸加2？ | 两边各补1层 |
| 公式为什么加1？ | 起点0也是一次放置 |
| (H,W) 和 (N,C,H,W) 哪个对？ | 前者是今天手算的一张二维表，后者明确表示批次与通道 |
| 卷积结果是不是最后分类答案？ | 它是特征图，完整分类网络还要继续处理 |
| 核大小写3，指3个参数吗？ | 3×3单通道核有9个权重，另有偏置时再加偏置参数 |
